# E2.316 verification and remaining coverage

Baseline: official main 5c7fa972 / v2.314 plus PR #24 E2.315, head 6211448. No newer main/release was present when work began.

## Actual Windows EXE tests

Built using source/compile.ps1 -DesktopOnly. Run the packaged FramingStudio.exe with --self-test and confirm-smoke.flag, using source/tests/confirmations316.js as checks.js. No automatic script-dialog acceptance. Profiles and models isolated from the user's desktop data.

- Default model: 27 assertions passed.
- Private copy of current HKIE 2025 Q5 model: 28 assertions passed.
- Covered: in-page visibility, text escaping, Cancel focus, duplicate rejection, Escape, validated prompt, type-delete cancel/confirm and exact single-undo restoration, new-type undo, dirty new/open cancellation, confirmed open and undo, stale save acknowledgement, actual native project file write, save acknowledgement clearing dirty state, in-page Help, and cancel/save/discard selections returning through WebView2 messages to C#.
- Current localhost browser: backup recovery, F04 delete confirmation visible, cancel, restored F02/beam layout/SB. Parsed project exports before/after are exactly equal. No new tab or port.
- 38 embedded modules synchronized; only app.js changed within the HTML module markers for E2.316. Unrelated HTML bytes differ only by version. Calculation engines, templates, report modules and the native Excel/report worker block are byte-identical to E2.315.
- E2.315 beam-feedback regression remains passing.

## EXE-specific findings and fixes

1. Dirty-close used Windows MessageBox, separate from browser confirmation. Now requests a shared in-page choice through asynchronous WebView2 messaging.
2. Page dirty state was cleared when export started, even if the native picker was cancelled. Now only a matching successful project write clears it; failures/cancellation preserve it.
3. Recovered backup could be dirty in the page while the native Unsaved flag was false. Close checks both states.
4. Desktop Help opened a missing usage-text file. Now opens the same built-in Help panel.
5. Test mode automatically accepted native dialogs. Removed to avoid masking these faults.
6. Native export overwrite confirmation is now in-page after file selection.

## Explicit coverage limits

Visible Windows save-picker cancellation, overwrite choice, and title-bar-close interaction await permission to open a visible QA window. The native message response paths and actual file write have passed EXE tests, but those visible interaction paths are not claimed as manually verified. No claim that every possible EXE defect has been eliminated. Native Excel/COM recalculation and A/B printing were not rerun; their code/templates are unchanged.

A separate --qa-profile <directory> argument is available for visible testing without touching the user's normal desktop backup/profile. Startup failure/already-running notifications remain native because an application page may not exist; they are not application confirmations. File choosers remain operating-system dialogs.
